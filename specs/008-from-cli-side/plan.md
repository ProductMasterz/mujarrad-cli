# Implementation Plan: CLI Observability, Documentation & Alpha Release Management

**Branch**: `008-from-cli-side` | **Date**: 2025-10-12 | **Spec**: [spec.md](./spec.md)

## Summary

This feature enhances the Mujarrad CLI with comprehensive observability, user experience improvements, and pre-release validation infrastructure. The primary requirement is to add production-grade logging with session tracking, real-time progress indicators, in-CLI documentation, installation branding, alpha version warnings, and automated integration testing before npm releases.

**Technical Approach**: Extend existing winston logging infrastructure with session management and API request/response logging. Implement structured log exports with compression. Add postinstall npm scripts for branding and welcome messages. Enhance Commander.js help system with examples and troubleshooting. Create integration test framework using Jest against staging API. Implement progress tracking using existing ora/cli-progress packages with TTY detection for CI/CD compatibility.

## Technical Context

**Language/Version**: TypeScript 5.3+ with Node.js 18+
**Primary Dependencies**: winston (logging), commander (CLI), ora (spinners), cli-progress (progress bars), chalk (colors), axios (HTTP), jest (testing)
**Storage**: File system (~/.mujarrad/logs/ for logs, ~/.mujarrad/config.json for CLI config)
**Testing**: Jest with ts-jest, integration tests against staging API
**Target Platform**: Cross-platform CLI (macOS, Linux, Windows) with Node.js 18+
**Project Type**: Single project (CLI tool)
**Performance Goals**: Log writes async (non-blocking), progress updates 1Hz minimum, postinstall <5s, log export compression >70%, integration tests <10 minutes
**Constraints**: Log file size <50MB, log retention 30 days, help output 80-column terminals, non-TTY environments must degrade gracefully
**Scale/Scope**: Single-user CLI tool, average session <5MB logs, support 1000+ file vault operations with detailed logging

## Phase 0: Research & Technical Decisions

**Status**: ✅ COMPLETE

**Output**: `research.md` with resolved technical decisions

**Research Areas**:

1. **Session ID Generation**: What format and generation strategy for unique session identifiers?
   - UUID v4 vs. timestamp-based vs. sequential
   - Collision probability and storage requirements
   - Integration with winston child loggers

2. **Log Rotation Strategy**: How to handle log file rotation without interrupting active sessions?
   - Winston built-in rotation vs. external log rotation tool
   - File locking on Windows vs. Unix
   - Tailable log files and max files configuration

3. **Sensitive Data Redaction**: What patterns to detect and redact in logs?
   - JWT tokens (Bearer prefix)
   - API keys and passwords
   - Common credential patterns (key=value, Authorization header)
   - Performance impact of regex scanning

4. **Progress Tracking in Non-TTY**: How to degrade gracefully in CI/CD environments?
   - TTY detection methods (process.stdout.isTTY)
   - Fallback strategies (periodic log messages vs. silence)
   - CI/CD environment variable detection (CI, CONTINUOUS_INTEGRATION, etc.)

5. **Log Export Compression**: What compression algorithm and format?
   - tar.gz vs. zip (cross-platform compatibility)
   - Node.js compression libraries (archiver, tar, adm-zip)
   - Compression ratio targets (>70% required by NFR-004)

6. **Postinstall Script Compatibility**: How to ensure postinstall works across npm, yarn, pnpm?
   - Package manager detection
   - Silent failure vs. error propagation
   - Windows console encoding (chalk color support)

7. **Alpha Version Warning Persistence**: Where to store disclaimer acknowledgment?
   - Config file (~/.mujarrad/config.json) vs. separate flag file
   - Per-version tracking vs. one-time acknowledgment
   - Migration strategy for existing users

8. **Integration Test API Mocking**: Should integration tests use real staging API or mocks?
   - Real API (slower, requires network, tests real integration)
   - Mock API (faster, no network, tests CLI logic only)
   - Hybrid approach (configurable via environment variable)

**Deliverable**: `research.md` documenting decisions, rationale, and alternatives for each area.

### 1.1 Data Model Design (`data-model.md`)

**Entities to define**:

- **LogSession**: CLI command execution session
  - Fields: sessionId (UUID), commandName (string), startTime (ISO 8601), endTime (ISO 8601), exitCode (number), metadata (object)
  - State transitions: STARTED → RUNNING → COMPLETED | FAILED
  - Relationships: One session has many LogEntry records

- **LogEntry**: Individual log record within a session
  - Fields: timestamp (ISO 8601), level (debug|info|warn|error), source (string), message (string), metadata (object)
  - Metadata schema: { apiRequest?, apiResponse?, error?, filePath?, operation? }
  - Validation rules: timestamp must be within session start/end range

- **AlphaDisclaimer**: User acknowledgment tracking
  - Fields: acknowledgedAt (ISO 8601), version (semver string), acknowledged (boolean)
  - Storage location: ~/.mujarrad/config.json
  - Lifecycle: Created on first CLI run, updated on version change

- **LogExport**: Compressed log archive metadata
  - Fields: exportedAt (ISO 8601), timeRange (object), includedSessions (array), compressionRatio (number), archivePath (string)
  - Archive structure: { metadata.json, logs/*.log, README.txt }
  - Validation: Verify archive integrity before returning path

- **TestReport**: Integration test execution results
  - Fields: reportId (UUID), executedAt (ISO 8601), environment (staging|production), results (array), overallStatus (PASS|FAIL)
  - Test result schema: { commandName, testCaseName, status, duration, error? }
  - Output format: JSON file + human-readable markdown summary

### 1.2 API Contracts (`contracts/`)

**CLI Command Schemas** (`cli-commands.yaml`):
```yaml
commands:
  - name: mujarrad logs export
    description: Export CLI operation logs as compressed archive
    options:
      - name: --since
        type: string
        description: Time range filter (e.g., "24h", "7d", "2025-01-01")
        required: false
      - name: --level
        type: string
        enum: [debug, info, warn, error]
        description: Minimum log level to include
        required: false
      - name: --output
        type: string
        description: Output path for archive (default: ./mujarrad-logs-{timestamp}.tar.gz)
        required: false
    examples:
      - mujarrad logs export --since "24h" --level error
      - mujarrad logs export --output ./debug-logs.tar.gz
```

**Log Format** (`log-format.json`):
```json
{
  "schema": {
    "timestamp": "ISO 8601 string",
    "level": "debug | info | warn | error",
    "sessionId": "UUID v4",
    "commandName": "string",
    "source": "string (module name)",
    "message": "string",
    "metadata": {
      "apiRequest": {
        "method": "string",
        "url": "string",
        "headers": "object (redacted)",
        "body": "object | null"
      },
      "apiResponse": {
        "status": "number",
        "headers": "object",
        "body": "object | null",
        "duration": "number (ms)"
      },
      "error": {
        "name": "string",
        "message": "string",
        "stack": "string"
      },
      "filePath": "string (optional)",
      "operation": "string (optional)"
    }
  }
}
```

**Log Export Archive Structure** (`log-export.yaml`):
```yaml
archive_structure:
  - metadata.json:
      description: Export metadata (time range, session count, compression ratio)
      schema:
        exportedAt: ISO 8601
        timeRange: { from: ISO 8601, to: ISO 8601 }
        includedSessions: number
        compressionRatio: number
        toolVersion: string
  - logs/:
      description: Directory containing individual log files
      files:
        - YYYY-MM-DD.log: Daily log file (JSON lines format)
  - README.txt:
      description: Human-readable export summary
      content: |
        Mujarrad CLI Log Export
        Exported: {timestamp}
        Time Range: {from} to {to}
        Sessions Included: {count}
        Compression: {ratio}%

        To view logs:
        1. Extract archive: tar -xzf mujarrad-logs-{timestamp}.tar.gz
        2. View logs: cat logs/YYYY-MM-DD.log | jq
```
